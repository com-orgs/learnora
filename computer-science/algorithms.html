Algorithms and Flowcharts

An algorithm is a precise sequence of steps for solving a problem. It can be written in everyday language, pseudocode or code. A flowchart makes the logic visible so that another person can follow and test it.

Learning time: 15–20 minutes · Beginner level · Free study resource

What you will learn

  • Define an algorithm and explain why order matters.
  • Break a task into small, testable steps.
  • Use sequence, selection and repetition.
  • Read basic flowchart symbols.

1. Design clear steps

Before writing an algorithm, make sure you understand the problem. An algorithm is a finite, ordered set of instructions that solves a defined task. A useful algorithm should be:

  • Clear: each instruction has one understandable meaning.
  • Ordered: steps happen in the correct sequence.
  • Finite: it reaches an end rather than repeating forever by accident.
  • Testable: you can try inputs and check whether the output is correct.

Start by identifying the input (information supplied), the process (what must happen) and the output (the result). Break a large problem into smaller parts; this is called decomposition.

Worked example: decide whether a mark is a pass

Suppose a practice task uses marks from 0 to 100 and defines a pass as 50 or more. Input: one mark. Process: check that it is within 0–100, then compare it with 50. Output: “Pass”, “Not yet” or “Invalid mark”.

INPUT mark
IF mark < 0 OR mark > 100 THEN
    OUTPUT "Invalid mark"
ELSE IF mark >= 50 THEN
    OUTPUT "Pass"
ELSE
    OUTPUT "Not yet"
END IF

This is pseudocode: a readable way to describe program logic without requiring one specific programming language. Notice that the valid range is checked before the pass condition.

2. Three control structures

Most beginner algorithms can be described using three control structures. A program can combine them.

  • Sequence: instructions run one after another in order.
  • Selection: a condition chooses which path to follow, commonly using IF and ELSE.
  • Iteration: a set of instructions repeats. A count-controlled loop repeats a set number of times; a condition-controlled loop repeats while a condition remains true.
Worked example: count five library books

A librarian wants to number five books from 1 to 5. The loop starts at 1, displays the current number, increases it by 1, and stops after 5.

FOR number ← 1 TO 5
    OUTPUT number
END FOR

The loop runs five times. If the stop condition were written incorrectly, it might miss 5 or run one extra time. Always test the first and last values.

Condition-controlled example:

Keep asking for a password while it is incorrect. The algorithm must also provide a safe stopping rule, such as a limited number of attempts; otherwise the loop could continue indefinitely.

3. Flowchart symbols

A flowchart is a diagram that shows the order and decisions in an algorithm. Use standard symbols consistently and connect them with arrows.

  • Oval (terminator): Start or End.
  • Rectangle (process): an action or calculation, such as adding 1 to a counter.
  • Parallelogram (input/output): read information or display a result.
  • Diamond (decision): ask a question with branches, often labelled Yes and No.
  • Arrow (flow line): shows which step happens next.
Worked example: pass-check flowchart plan
  1. Oval: Start.
  2. Parallelogram: Input mark.
  3. Diamond: Is mark below 0 or above 100? Yes → parallelogram: display “Invalid mark” → End. No → continue.
  4. Diamond: Is mark at least 50? Yes → display “Pass”. No → display “Not yet”.
  5. Both result paths lead to an oval: End.

Every decision branch should be labelled. Each route should reach an appropriate next step and eventually finish.

Flowcharts are useful for seeing a program's path, but a large flowchart can become difficult to read. For a long solution, split the task into smaller parts.

Common mistakes to avoid

Writing vague instructions such as “do the calculation” without saying which values or operation to use.
Putting steps in the wrong order, such as comparing a mark before checking whether it is within the allowed range.
Forgetting boundary values such as 0, 50 or 100, or failing to test equal values.
Creating a decision diamond without clearly labelled Yes/No branches.
Writing a loop with no clear stopping condition, which can cause an infinite loop.
Testing only one normal input. Also test invalid, smallest, largest and boundary inputs.

Practice exercises

Try each task before opening the suggested reasoning. There can be more than one correct algorithm if the steps are clear and solve the task.

1. Write a library-book algorithm

Write five or more ordered steps for borrowing a book.

Suggested answer: (1) Start. (2) Search for the book. (3) Check whether it is available. (4) If unavailable, tell the reader and finish. (5) If available, scan the reader card and book. (6) Record the loan and due date. (7) Give the book and due date to the reader. (8) End. A school may use different steps, but the availability decision and clear finish should be included.

2. Check whether a number is even

Describe an algorithm that reports whether an integer is even or odd.

INPUT number
IF number MOD 2 = 0 THEN
    OUTPUT "Even"
ELSE
    OUTPUT "Odd"
END IF

Why it works: MOD gives the remainder after division. An integer divisible by 2 has remainder 0. Test values such as 4, 7, 0 and −2 if negative integers are allowed.

3. Choose the correct flowchart symbol

Which symbol represents a decision?

Answer: A diamond, because it asks a question and sends the flow along different branches.

4. Trace a count-controlled loop

What values are displayed by FOR n ← 2 TO 4?

Answer: 2, 3 and 4, in that order. It runs three times when the end value is included, as in this pseudocode convention.

5. Test the pass algorithm

For a valid mark from 0 to 100, with 50 as the pass mark, what should happen for 0, 49, 50, 100 and 101?

Answer: 0 → Not yet; 49 → Not yet; 50 → Pass; 100 → Pass; 101 → Invalid mark. The values 49 and 50 check the boundary around the pass threshold; 0 and 100 check the valid range; 101 checks an invalid value.

Teacher / Parent Suggested Answer Key
  1. INPUT A, B
IF A > B THEN
    OUTPUT A
ELSE IF B > A THEN
    OUTPUT B
ELSE
    OUTPUT "Equal"
END IF
    The equal case must be handled; accepting either order of the first two conditions is fine if the equal case is correct.
  2. Start → input mark → decision “mark below 0 or above 100?” Yes: output Invalid → End. No: decision “mark at least 50?” Yes: output Pass → End; No: output Not yet → End. Use a diamond for each decision, parallelograms for input/output, and ovals for start/end.
  3. FOR n ← 1 TO 6; OUTPUT n; END FOR. It repeats six times when the end value is included.
  4. Example: 49 → Not yet; 50 → Pass; 101 → Invalid. Other valid test sets with expected outputs accepted.
  5. Finite means it reaches an end; unambiguous means different readers can follow the same instruction consistently. Both make the solution reliable and testable.

Lesson recap

  • An algorithm is a clear, ordered and finite set of steps for solving a defined problem.
  • Identify inputs, processes and outputs before writing the steps; decomposition breaks a large problem into smaller parts.
  • Sequence runs steps in order, selection chooses a path, and iteration repeats steps.
  • Flowcharts use standard symbols and labelled arrows to show the logic.
  • Test normal, invalid and boundary values; trace loops to check how many times they run.
